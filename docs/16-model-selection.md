## 1. 前置结论：境外模型在中国消费级场景基本不可选

先说这一条，因为它会直接淘汰一批候选。

这个产品处理两类数据：

| 数据 | 敏感程度 | 说明 |
| --- | --- | --- |
| 宠物照片 | **中高** | 画面里有家里的内饰、可能的家人、位置信息（EXIF） |
| **家庭环境音频** | **极高** | 麦克风录到的**不只是猫叫**，还有全家人的对话 |

把家庭音频送出境，在《个人信息保护法》下属于需要单独同意 + 安全评估的场景。
即使不考虑合规，一个「把你家对话传到海外服务器」的消费级产品也不该存在。

**所以 GPT / Gemini / Claude 系列不是「贵或慢」，而是「不可选」。**
（例外：如果产品只面向海外市场，结论反转 —— 但那就不是这个产品了。）

DashScope 华北2 同时解决合规与延迟：数据不出境，物理距离近。

> **选型纪律**：把合规放在能力之前。否则你会先优化三个月能力，
> 然后发现整套架构不能上线。

## 2. LLM：`qwen-plus`

### 候选与价格（华北2）

官方定价页以美元计，下表按 7.2 折算为人民币（元/百万 token）：

| 模型 | 输入 | 输出 | 备注 |
| --- | --- | --- | --- |
| `qwen-turbo` | ¥0.32 | ¥0.63 | 官方已建议迁往 Flash |
| **`qwen-plus`** | **¥0.83** | **¥2.07** | ← 选它 |
| `qwen-max` | ¥2.48 | ¥9.91 | 无阶梯计价 |
| `qwen3-vl-flash` | ¥0.16 | ¥1.55 | **多模态，比 qwen-plus 还便宜** |
| DeepSeek V4-Flash | ≈¥1.5 | ≈¥4.5 | 官方价，谷时更低 |

### 为什么是 `qwen-plus` 而不是最便宜的

我们的对话任务的实际构成：

```
人设扮演            ← 需要稳定的角色一致性
记忆注入            ← 需要准确使用注入的上下文
守卫合规            ← 需要遵守「不编造」的指令约束
─────────────────────────────
硬推理              ← 几乎没有
```

这不是一个推理密集型任务。但**「不编造」这条指令的遵循度**直接决定产品是否违反
安全不变量（I1–I18）—— 而指令遵循质量随模型规模下降得**比成本慢**。

### 为什么不用 DeepSeek

单看单价 DeepSeek 更便宜，我们的成本结构里 LLM 也不是大头（见 §8）。
**用一部分单价换「视觉 + 文本 + 向量 + 语音同一家」，是划得来的**：

- 一个 API key、一套错误码、一个限流策略、一个计费面板
- 视觉与文本用同一套 `httpx` 客户端与重试分类（项目里已实现）

> **这不是「懒」，而是一个明确的阈值判断**：
> 当 LLM 月成本超过约 **¥3,000** 时值得重新评估（此时多供应商的复杂度会被分摊）。
> 在那之前，统一供应商的工程收益大于价差。

### ⚠️ 待验证

- `qwen-plus` 的**思考模式**输出价是 ¥1.147/¥4.588 —— 如果误开，成本翻倍。默认关闭。
- 人设稳定性**没有评测数据**。这是 U1（校准）的一部分，不是模型选型能解决的。

## 3. VLM：`qwen3-vl-flash` 主力 —— **但这是全篇最需要警惕的一项**

### 先说反证：通用 VLM 在动物任务上表现很差

我找到了一篇直接相关的论文（*Scientific Reports* 2025，狗的情绪识别）：

| 发现 | 内容 |
| --- | --- |
| 数据集 DE | GPT-4o 约 **76.6%**，Gemini 明显更差 |
| 数据集 LRc（更难） | **没有任何模型超过 0.6**；GPT-4o 在 1000 张图里只判对 **12 张** |
| **失败机制** | 模型**不看动物生物特征**，而是靠**背景/环境线索**：草地/沙发→开心，诊所/栏杆→悲伤 |
| 对照 | 一个小型专用模型（DINO-ViT）在同一 LRc 数据集上达到 **89%** |
| 结论 | 「**尚不适合**可靠、有生物学依据的犬类情绪识别」 |
| 一个意外 | 新模型倾向于**拒答**而非乱答；用强制 prompt 能提高回答率但**不提高准确率** |

**三条对我们的直接意义：**

1. **通用 VLM 不能做宠物情绪推断。** 它读的是场景，不是动物。
2. **专用小模型 >> 通用大模型**（89% vs <60%）。模型规模不是这个任务的瓶颈。
3. **「拒答」是正确行为。** 这与我们「宁可显式标记缺失，也不给假数字」的设计同向 ——
   但它是模型自发的，不是我们能控制的，所以仍需在契约层强制（见下）。

### 再说我们的任务：与上面**不同**

我们要求 VLM 做的不是情绪推断，而是**视觉属性抽取**：
毛色、脸型、眼色、耳型。这是描述性任务，接近 OCR，而不是情感推理。

**但背景捷径的风险依然存在** —— 如果 prompt 里问「它胖吗」，模型可能读沙发。
所以下面这条是硬约束。

### 候选与价格

| 模型 | 输入 | 输出 | 相对 `qwen-vl-max` |
| --- | --- | --- | --- |
| **`qwen3-vl-flash`** | **¥0.16** | **¥1.55** | **输入 1/10，输出 1/2.7** |
| `qwen-vl-plus` | ¥0.83 | ¥2.07 | 1/2 |
| `qwen3-vl-plus` | ¥1.03 | ¥10.32 | 输出反而贵 2.5 倍 |
| `qwen-vl-max` | ¥1.66 | ¥4.13 | 基准 |

### 结论与理由

**`qwen3-vl-flash` 做主，`qwen-vl-max` 只在低置信时复核。**

- 输入价差 **10 倍**。照片分析里输入占绝对主体（一张图 1000–2000 token），
  所以总价差接近 10 倍，不是 2 倍。
- Qwen3-VL 是比 Qwen-VL 更新的一代，Flash 档在属性抽取这类任务上够用。
- 「主力 + 难例复核」是**成本可控且可度量**的两级策略：
  复核率本身就是一个可监控指标。

### ⚠️ 必须在接真实 API 前做的事

**自建一个 50–100 张的小评测集**（找养猫的人，每张图人工确认毛色/脸型/眼色）。

理由：`qwen3-vl-flash` 便宜不代表在**我们的任务上**够用。
项目已有的 `live_check.py` 只验证「API 通了」，不验证「抽得对」。
两者是不同的问题 —— 这正是 B16/B17 的教训（**代码能跑 ≠ 结果正确**）。

评测集要测的是**逐字段准确率**，不是整体「感觉还行」。

### 🔴 硬约束：不得输出体况数值

我查了 BCS 的文献，结论比预期更悲观：

| 发现 | 数据 |
| --- | --- |
| 评估者间一致性 | 完全一致约 **50%**；Kendall's W = 0.79–0.90 |
| 理想体重 vs 超重误分类率 | **15.5%** |
| **拍摄角度的影响** | 同一只猫（真实 BCS 9），蜷缩姿势遮挡腹部 → 被读成 **6–7** |
| 长毛猫 | 样本太少，**连毛发长度的影响都无法评估** |
| 最优方案 | 9 名评估者**多数投票**，偏差 0.08（单人 0.39） |
| 作者建议 | **统一拍摄方案（顶视 + 正视 + 侧视）、标准光照**；组间比较最小 BCS 差异 **2 分** |

**这意味着：**

1. **多图不是加分项，是必需项** —— 而且应该**引导用户拍特定角度**。
   项目 P0 已经做了多图取交集，但那是为了防幻觉，**不是为了消视角偏差**。
   现在有了文献依据：**应从「随便多拍几张」改为「引导拍顶/正/侧三视角」**。
2. **长毛猫应直接 withhold**，不是「低置信」。
3. **永远不声称 1 分的变化有意义**（文献门槛是 2 分）。
4. 单人读数不可信，**我们就是那个「单人」** → 只能给区间与不确定性，不能给点数。

契约层已有 `total: null` 的强制 withhold 机制，这条文献结论**验证了该设计的必要性**，
并给出了更具体的门限。

## 4. 猫叫理解：**不接外部 API**（最反直觉的一项）

### 关键证据一：人类自己分不清

一篇研究让成年人对三种情境（等待食物 / 隔离 / 梳毛）的猫叫做分类：

| 情境 | 人类准确率 |
| --- | --- |
| 等待食物 | 40.4% |
| 梳毛 | 32.9% |
| 隔离 | 26.7% |
| **随机水平（三分类）** | **33.3%** |

论文原话：**「从未显著高于随机水平」**。而且最有代表性的叫声（medioid）
比偏离典型的叫声更容易被认对。

### 关键证据二：自动化方法报告 95.94%，但**很可能被高估**

同一批情境，DAG-HMM 报告 **95.94%**（对比 SVM 78.5%、universal HMM 76.2%）。

但我核对了方法细节：

| 问题 | 论文的说法 |
| --- | --- |
| 448 个录音来自多少只猫？ | 招募了 **21 只**（10 缅因 + 11 欧短），**未说明实际贡献数** |
| 是否按个体分组做交叉验证？ | **未说明** |
| 跨个体泛化？ | **未讨论** |
| 是否可能个体内泄漏？ | **未讨论** |

论文自己写了「猫被**反复**暴露于三种情境」—— 意味着同一只猫有多次录音。
若十折交叉验证**没有按个体分组**，同一只猫的声音会同时出现在训练集和测试集里，
分类器学到的是**这只猫的个体特征 + 录音环境**，而不是情境本身。

> ⚠️ **这是我的推断，不是论文的结论。** 论文没说它错了，但它也没排除。
> 在 21 只猫 / 448 条录音的规模下，这是**必须排除**才能采信的数字。

### 人的 ~33% 与机器的 ~96% 之间那个差距

一个三分类任务，人类在随机水平，机器 96% —— 要么机器真的找到了人类听不到的线索，
要么验证协议有问题。**在协议被澄清之前，不能按 96% 规划产品。**

### 结论

**保持自研声学特征 + 分层贝叶斯，不接外部猫叫 API。**

理由不是「我们做得更好」（我们做的肯定不如 96%），而是：

1. **没有可用的外部方案。** 有厂商把「声音识别分析」列为能力项，但**无任何公开验证**。
2. **接外部 API 会摧毁本项目的核心价值。** 我们的后验是**可归因的**
   （每个特征的 log-odds 贡献是一个数字）；一个不透明的 96% 相比起来**信息更少**，
   因为用户无法核查，我们无法校准。
3. **人类基准线反而是产品设计的依据** —— 见下。

### 这条证据**支撑**（而非削弱）现有设计

> 「**人类自己也分不清**（26–40%，接近随机）。
> 所以我们不给你一个确定的答案，而是一个**带不确定性的候选排序 + 可核查的证据链** ——
> 让你用自己知道的情境信息去做最后判断。」

这是整个行为解释器存在的最好理由。如果人类能听出来，产品就该直接给答案；
正因为听不出来，「证据 + 不确定性」才是**唯一诚实的形态**。

**待办**：把这个人类基准线写进 `docs/03-behavior-interpreter.md`，
它比任何技术论证都更能说明「为什么要显示后验而不是一句话」。

## 5. Embedding：换 `text-embedding-v4`，保持 1024 维

| 指标（1024 维） | v3 | v4 | 提升 |
| --- | --- | --- | --- |
| MTEB 综合 | 63.39 | **68.36** | +4.97 |
| MTEB Retrieval | 55.41 | **59.30** | **+3.89** |
| CMTEB 综合（中文） | 68.92 | **70.14** | +1.22 |
| CMTEB Retrieval（中文） | 73.23 | **73.98** | +0.75 |
| **价格** | ¥0.5/M | **¥0.5/M** | **相同** |

- v4 支持 64–2048 维，我们保持 **1024**（与 `vector(1024)` schema 一致，无需改表）
- **v3 与 v4 的向量不能混用** → 必须全量重建索引
- Batch 接口半价（¥0.25/M）

**结论：换 v4。同价位纯白拿的提升。**

**但要诚实说明预期收益有多大**：我们检索的是**中文口语化记忆**
（「它很怕吸尘器」），中文指标 CMTEB Retrieval 只涨 **+0.75** —— 因为 v3 中文本来就不弱。
大涨的 MTEB 是英文/多语言项，对我们用不上。

所以真实收益是**「小但免费」**，不是「大幅改善检索」。不要用 +3.89 去说服自己。

**决策依据**：同价 + 略优 → 换。重建索引在 P0 规模下是几秒钟的事。

## 6. ASR：`paraformer-v2`

| 方案 | 价格 | 依据 |
| --- | --- | --- |
| **`paraformer-v2`** | **$0.000012/秒 ≈ ¥0.0052/分钟** | 官方定价 |
| `paraformer-realtime-v2` | $0.000035/秒 | 流式，3 倍价 |
| `qwen3-asr-flash` / Fun-ASR | $0.000032/秒 | 更贵但覆盖方言 |
| **自托管 SenseVoice-Small** | 电费 | **CPU 上 17.2× 实时**；GPU 169× |

**结论：P0 用 `paraformer-v2`；自托管 SenseVoice 作为隐私后手。**

- 内置 VAD + 标点 + 时间戳，一次调用解决分段问题
- ¥0.0052/分钟意味着 1000 用户 × 5 分钟/天 ≈ ¥780/月 —— 便宜到不需要优化
- **隐私后手**：SenseVoice 在 **CPU 上 17 倍实时**，意味着**不需要 GPU 也能自托管**。
  当「家庭音频不出本地」成为卖点时，这是一条真实可走的路径（不是理论选项）。
- 参照：Whisper-large-v3 在 GPU 上 13.4× 实时，**比 FunASR 的 CPU 推理还慢**。

**注意**：ASR 只用于**用户语音输入**。
猫叫走的是自研声学特征路径（§4），**不要把猫叫喂给 ASR** —— 它会被转成无意义的文字。

## 7. TTS：`cosyvoice-v3.5-flash` —— **但它是最贵的组件**

| 模型 | 价格（元/万字符） |
| --- | --- |
| **`cosyvoice-v3.5-flash`** | **¥0.84** |
| `qwen3-tts-flash` | ¥0.83 |
| `cosyvoice-v3.5-plus` | ¥1.58 |

单看单价很便宜。但**按使用量算，它是成本大头**（见 §8）：
每次语音回复 50 字 × 20 次/天 = 1000 字/天/用户
→ 1000 用户 = 100 万字/天 → **¥84/天 ≈ ¥2,520/月**。

**比较**：同一批用户的 LLM + 视觉 + 向量 + ASR 加起来约 ¥1,300/月。

> **TTS 一项比其余所有模型加起来贵一倍。**

**结论**：
1. TTS 属于 P2（项目决策 D20 已把主动触达推到 P2 —— 与这个成本结构一致，是巧合但方向正确）
2. 上 TTS 前**必须先做缓存**：陪伴类产品的回复有大量重复
   （「我在这儿呢」「今天过得怎么样」），缓存命中率高
3. **不要做声音克隆**。它既是成本放大器，也是合规雷区（生物特征信息）。

## 8. 成本模型与「自托管阈值」

### 单用户月成本估算

假设：10 次对话/天、2 张照片/周、3 段语音/天、20 条语音回复/天（若开 TTS）

| 组件 | 用量/月 | 单价 | 成本 |
| --- | --- | --- | --- |
| LLM | 300 次对话 | ¥0.0035/次 | **¥1.05** |
| 视觉 | 8.6 张 | ¥0.0008/张（flash） | **¥0.01** |
| Embedding | ~200 条记忆 | — | **< ¥0.01** |
| ASR | 2700 秒 | ¥0.000086/秒 | **¥0.23** |
| **小计（不含 TTS）** | | | **≈ ¥1.29** |
| TTS | 30,000 字符 | ¥0.84/万 | **¥2.52** |
| **总计（含 TTS）** | | | **≈ ¥3.81** |

### 乘上用户规模

| 用户数 | 不含 TTS | 含 TTS |
| --- | --- | --- |
| 1,000 | ¥1,290/月 | ¥3,810/月 |
| 10,000 | ¥12,900/月 | ¥38,100/月 |

按 ¥15/月订阅，10,000 用户 = ¥150,000 收入 → 模型成本占 **8.6%–25%**。
**可行，但 TTS 是从 8.6% 跳到 25% 的那个开关。**

### 自托管到底划不划算？—— **不划算**

直觉上「量大了自托管更便宜」。算一下视觉（最可能自托管的组件）：

| 方案 | 单位成本 |
| --- | --- |
| `qwen3-vl-flash` API | ¥0.0008/张 |
| 自托管 VLM（A10 租用 ¥3/小时，2 秒/张） | **¥0.0017/张** |

**自托管反而贵一倍**，还没算运维、扩缩容、模型更新、多租户隔离。
GPU 利用率到不了 100%，实际差距更大。

**结论：自托管的理由只能是「隐私/合规」，不能是「省钱」。**
这个结论违反直觉，但它是算出来的 —— 而且它意味着
**架构上不需要为「将来省钱而自托管」预留任何东西**。

**唯一的例外是 ASR**：SenseVoice 在 CPU 上 17× 实时，不需要 GPU 就能跑，
所以「家庭音频不出本地」这条隐私路径的成本是真实的、可承受的。

## 9. 调研改变了项目里的三件事

| # | 原来 | 现在 | 依据 |
| --- | --- | --- | --- |
| 1 | 多图「取交集防幻觉」 | **引导拍顶/正/侧三视角** | BCS 文献：视角会让同一只猫被读成 6 或 9 |
| 2 | 长毛猫 →「低置信」 | **长毛猫直接 withhold** | 文献样本不足以评估毛发长度影响 |
| 3 | 行为解释器的依据是「声学特征有信息量」 | 依据改为**「人类自己也接近随机」** | 人类 26–40% vs 随机 33% |

第 3 条的改动最重要：**它把一个技术主张换成了一个产品主张。**

原来的论证是「我们能从声学推断情境」，这在文献上**站不住**
（95.94% 的跨个体泛化未验证）。

新论证是「**人类自己听不出来，所以我们给证据而不是答案**」——
这个论证**有直接证据支持且无法被反驳**，并且它导出的设计
（候选排序 + 不确定性 + 可核查证据）恰好和现有实现一致。

> 同样一套设计，换了一个**能站住的论证**去支撑它。
