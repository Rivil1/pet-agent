# 08 · RAG 与 Agent 技术能力体现地图

> 本文档回答一个问题：**这个项目里，RAG 和 Agent 的能力到底体现在哪？**
>
> 结论先行：**体现在决策和边界上，不体现在技术名词上。**

## 0. 为什么「我用了 RAG」是无效陈述

| 说法 | 面试官的心理反应 |
|---|---|
| 「我用了 RAG」 | 「切片 + embedding + top-k + 塞 prompt，15 行代码。」 |
| 「我用了 LangGraph」 | 「画了个图调几次 API 而已。」 |
| 「我用了向量数据库」 | 「Milvus 装完就会用。」 |

**问题不在于轻蔑，而在于这些陈述没有区分度**——它们无法区分一个调通 demo 的人和一个设计过系统的人。

有区分度的陈述长这样：

> 「我把检索分成了两种访问模式：稳定身份事实用主键直读，**故意不走向量检索**。
> 因为身份只有一份正确答案，扔进相似度检索会主动引入不确定性。
> 只有事件层用混合检索。另外我在写入侧做了准入和去重强化，
> 因为 RAG 的质量瓶颈通常在写入，不在检索。」

这段话里没有一个技术名词是新的，但它体现了**判断力**。

## 1. RAG 能力阶梯

### 1.1 阶梯

| 级别 | 特征 | 典型说法 |
|---|---|---|
| L0 玩具 | 切片 → embedding → top-k → prompt | 「我用了 RAG」 |
| L1 工程 | 混合检索、重排序、元数据过滤 | 「我用了混合检索 + rerank」 |
| L2 系统 | 查询改写、多跳、**命中率评测** | 「我跑了 recall@k 对比」 |
| L3 判断力 | **写入侧质量 / 拒答策略 / 何时不用检索 / 可评估性** | 见下 |

**关键认知**：多数人只优化 L1（检索侧），而 L3 才是真正的分水岭。

### 1.2 本项目落在哪：**写入侧 > 检索侧**

`docs/04-memory.md` 里，检索管线只占 §4，而写入决策占了 §3（去重、冲突、准入、投毒防护）。

**为什么这是对的**：

```
垃圾进 → 无论检索多好，出来都是垃圾
        （Garbage in, garbage out）

但反过来：
优质写入 + 朴素检索 → 结果依然可用
```

本项目检索规模极小（单宠物几十到几百条记忆），**瓶颈根本不在检索性能**。
瓶颈在于：什么该进库、重复了怎么办、矛盾了怎么办、模型自己猜的能不能进库。

**面试表述**：

> 「RAG 的质量瓶颈通常在写入侧而不是检索侧。
> 我花最多精力的是三件事：记忆准入策略（什么值得长期保存）、
> 去重强化（同一信息说三次产生 1 条记忆 + support_count=3，而不是 3 条）、
> 以及冲突消解（用取代链而不是覆盖，因为『上个月喜欢、这周不喜欢』是演变不是矛盾）。」

### 1.3 拒答策略：RAG 最被忽视的一环

**这是幻觉的主要来源，也是最能体现水平的地方。**

```python
# ❌ 玩具做法
memories = vector_store.search(query, k=5)
prompt = f"已知信息：{memories}\n请回答：{query}"
# 检索为空时，memories = ""，模型用常识补全 → 幻觉

# ✅ 本项目做法（docs/04-memory.md §5）
{
  "known_facts": [...],
  "retrieval_note": "以上为检索到的记录。未在其中的信息即为没有记录，不要推测或使用常识补全。"
}
```

除此之外还有**结构性保障**：召回为空时由 `companion_agent` 明确报告「没有相关记录」，
再由 `response_guard` 检查断言是否有据（对照检索结果的来源）。

**可评估**：评测项 E2——问档案中不存在的信息，误答率必须为 0。

**面试表述**：

> 「检索不到时，系统必须说『没有记录』，而不是让模型用常识补全。
> 我在 prompt 里显式说明这点，并在守卫节点检查每个事实性断言是否有检索来源。
> 这条有对应评测项，要求误答率为 0。」

### 1.4 知道**何时不用**检索

`docs/04-memory.md` §1 的核心决策：

| 层 | 访问模式 | 理由 |
|---|---|---|
| Profile 身份层 | **主键直读** | 身份只有一份正确答案，相似度检索会引入不确定性 |
| Episode 事件层 | 混合检索 | 语义变体多，必须用向量 |
| Session 会话层 | 直读 | 就是当前上下文 |

**面试表述**：

> 「能精确定位的数据，我不使用相似度去找。
> 身份事实如果塞进向量库，会出现『检索到三条互相冲突的颜色描述』这种荒谬情况，
> 然后模型开始和稀泥。这是一个 RAG 设计决策——**决定什么时候不用检索**。」

### 1.5 可评估性

「我用了 RAG」→「我在评测集上跑了 RAG」：

| 指标 | 用途 |
|---|---|
| `recall@k` | 检索侧：该召回的有没有召回 |
| `MRR` | 排序质量：正确结果排在第几 |
| **有据陈述率 / 无据陈述率** | 生成侧：回答里有多少断言能追溯到检索结果 |
| **污染率** | 隔离性：多宠物记忆交叉污染条数（要求 0） |

详见 [DESIGN.md](DESIGN.md) §6（评测体系）。

## 2. Agent 能力阶梯

### 2.1 阶梯

| 级别 | 特征 | 典型说法 |
|---|---|---|
| L0 玩具 | 一个 prompt + 几个 tool | 「我做了 Function Calling」 |
| L1 编排 | 多节点、条件路由 | 「我用 LangGraph 编排了 6 个节点」 |
| L2 工程 | 状态管理、失败降级、可观测性 | 「每个节点有独立的降级策略」 |
| L3 判断力 | **控制流所有权 / 澄清决策 / 副作用隔离 / 刻意不用循环** | 见下 |

### 2.2 核心问题：**控制流归谁**

这是 Agent 工程最本质的问题，也是面试最能拉开差距的地方。

| 方案 | 优点 | 缺点 |
|---|---|---|
| 模型自主决定下一步（ReAct） | 灵活，能处理未预期任务 | 不可预测、不可测、成本不可控、失败不自知 |
| 代码决定控制流（固定图） | 可测、可控、成本可预算 | 僵化 |

**本项目的选择：框架级控制流（代码）+ 局部自主（模型）**

```
代码决定：      路由走向、失败降级、守卫规则、记忆写入规则、概率计算
模型决定：      措辞表达、槽位抽取、候选记忆抽取、建议观察项生成
```

具体体现：

| 决策点 | 归属 | 位置 |
|---|---|---|
| 走哪条分支 | **代码** | `understand_input` 输出 enum + 阈值，图决定走向 |
| 是否澄清 | **代码** | `route_confidence < 阈值` → 强制走 `clarify_ask` |
| 意图概率 | **代码** | 朴素贝叶斯计算，见 `docs/03` §3 |
| 是否放行回复 | **代码** | `response_guard` 可拒绝与重写 |
| 记忆能否入库 | **代码** | 准入规则 + 冲突判定，见 `docs/04` §3 |
| 怎么措辞 | 模型 | — |
| 抽取什么字段 | 模型 | 但字段契约由 Pydantic 约束 |

**面试表述**：

> 「我把控制流的所有权分成了两层：节点间的路由、降级、守卫、写入规则全部由代码决定，
> 模型只在节点内部负责语义工作。
> 原因是路由错误的代价是**写入错误记忆**，会污染长期状态；
> 而概率计算如果交给模型，同一段音频两次调用可能给出不同置信度，『证据』就不成立了。」

### 2.3 澄清决策：**宁可多问一句**

`docs/01-architecture.md` §5 的关键设计：

```python
class InputIntent(str, Enum):
    CHAT = "chat"
    MEMORY_QUERY = "memory_query"
    TRANSLATE_BEHAVIOR = "translate_behavior"
    PROFILE_UPDATE = "profile_update"
    RECORD_EVENT = "record_event"
    AMBIGUOUS = "ambiguous"      # ← 独立分支，不是 fallback 到 chat
```

**为什么 `AMBIGUOUS` 必须是独立分支**：猜错意图 → 写入错误记忆 → 长期状态被污染。
这个代价远高于多问一句的体验损失。

**面试表述**：

> 「路由不确定时我没有 fallback 到闲聊，而是走独立的澄清分支。
> 因为猜错意图会导致错误记忆写入长期库，这个代价比多问一句高得多。
> 这是一个把『长期状态正确性』置于『交互流畅度』之上的决策。」

### 2.4 降级分级：**正确性降级可见，体验降级静默**

`docs/01-architecture.md` §6：

| 失败点 | 降级 | 用户可见性 |
|---|---|---|
| 声学特征提取失败 | 退化为文本推断 | **必须标注证据模式** |
| 记忆检索为空 | 说「没有记录」 | **显式说明** |
| 视觉抽取部分失败 | 标注照片覆盖度 | **显式提示** |
| TTS 失败 | 无语音 | 静默 |
| 记忆抽取失败 | 本轮不写 | 静默 |

**玩具项目没有降级，一挂就挂。** 有分级降级策略是 L2 以上的标志。

**面试表述**：

> 「我把降级分成了两类：影响**正确性**的降级必须用户可见，
> 比如声学分析失败时必须标注『本次为纯文本推断』，否则用户会以为系统真的分析了音频；
> 影响**体验**的降级可以静默，比如 TTS 失败不影响主响应。」

### 2.5 副作用隔离

记忆写入是**副作用**，不应阻塞主响应：

```
response_guard → tts_output → 返回用户
                                   ↓
                            memory_writer（异步）
```

**并且**：写入失败不得影响已经生成的回复（`docs/01` §6）。生产环境应改为后台任务或消息队列。

**面试表述**：

> 「记忆写入是副作用，我把它放在响应之后，并且失败不影响主响应。
> 更重要的是**宁可不写，不可写错**——因为错误记忆会被后续检索放大。」

### 2.6 可观测性

`AgentState` 里有专门的 trace 字段：

```python
errors: Annotated[list[NodeError], operator.add]
node_trace: Annotated[list[NodeTrace], operator.add]
```

使用 `operator.add` 归约，使并行分支的写入能正确合并（LangGraph reducer 语义）。

**面试表述**：

> 「每个节点都有 trace，记忆里保留了每条记忆的来源与置信度，
> 行为解释保留了当时的特征值与先验版本。
> 这样任何一个结论都能回答『当时为什么这么判断』。」

## 3. 刻意不用的技术（最高级的体现）

**主动说明「我刻意没用某技术，理由是…」，比会用更值钱。**
因为它证明你理解技术的**适用边界**，而不是在堆名词。

| 技术 | 为什么不用 | 面试表述 |
|---|---|---|
| **ReAct / 反思循环** | 任务边界清晰（5 类意图分类 + 领域内推理）。循环只会增加不确定性、token 成本与不可测性，不会提升正确率 | 「这个场景不需要 ReAct。任务边界是封闭的 5 类路由，循环带来的不确定性远超收益。而且行为解释要的是**可复现的概率计算**，不是模型自由推理——自由推理恰好会破坏证据可追溯性。」 |
| **模型自主选工具** | 路由是分类问题，结构化输出 + 阈值可评测、可调参。模型自主 function calling 的失败模式是「选错工具且不自知」 | 「我让模型做分类，让代码做决策。模型自主选工具的失败模式是静默选错，这在会写长期记忆的系统里代价太大。」 |
| **Milvus / 自建向量库** | 检索规模小（单宠物数百条）。跨库一致性成本 > 性能收益 | 「不是能力问题，是一致性成本。我需要『先结构化过滤再向量检索』，pgvector 同库 JOIN 最直接，避免向量删了关系记录没删。」 |
| **Profile 层向量检索** | 见 §1.4 | 「能精确定位的数据不用相似度去找。」 |
| **微调模型** | 数据量不足；且需要的是**可审计的推理**而非隐式知识 | 「微调会让置信度变得不可解释，而我的核心要求是证据可追溯。」 |
| **端到端多模态大模型直接出答案** | 会失去证据链与可复现性 | 「我不用 VLM 直接『听』叫声下结论，因为那样 `evidence` 数组就只能由模型生成，那是讲故事不是证据。」 |

## 4. 自我批判：本项目的薄弱点（提前准备）

**主动交代弱点比被问出来强。** 而且要说清楚「为什么这个弱点在本场景不重要」。

| # | 弱点 | 被问到时怎么答 |
|---|---|---|
| W1 | 检索规模小，讲不了召回率/延迟优化 | 「这个场景的瓶颈不是检索性能。单宠物记忆量在数百条量级，暴力检索都够用。所以我优化的重点是写入侧质量和拒答策略——**这才是 RAG 在真实业务里失败的地方**。」 |
| W2 | 没有多跳检索 | 「宠物记忆基本是单跳的。唯一接近多跳的是行为解释——它做了『声学特征检索 + 个体似然 + 群体先验』的融合，但这是概率融合不是图遍历。」 |
| W3 | Agent 是 DAG 不是循环 | 「刻意的选择，见 §3。任务边界封闭时，固定图的可测性远比灵活性重要。」 |
| W4 | 没有真实并发与压测 | 「单机部署，没做压测。但状态设计上是无状态的（所有状态在 `AgentState` 里显式传递，节点不持有跨请求状态），所以水平扩展没有障碍。」 |
| W5 | 评测集规模小 | 「评测集是我自己构造的，规模有限。但它的价值在于**建立了可执行的断言**，比如『`system_inference AND ACTIVE` 条数恒为 0』这种不变量检查，比跑分更有意义。」 |

## 5. 面试问答映射表

| 面试官会问 | 你的回答落点 | 对应文档 |
|---|---|---|
| 「RAG 怎么做的？」 | 三层访问模式分离；**身份层不做向量检索** | `04` §1 |
| 「怎么保证不幻觉？」 | 拒答策略 + `retrieval_note` 显式声明 + 守卫检查断言来源；评测要求误答率 0 | `04` §5、`05` |
| 「记忆重复怎么办？」 | **强化而非重复插入**：`support_count += 1`，同时作为晋升触发条件 | `04` §3.2 |
| 「前后矛盾怎么办？」 | 冲突判定三条件，**时间范围重叠是关键**；取代链保留历史 | `04` §3.3 |
| 「模型自己猜的会存下来吗？」 | **绝不**。`SYSTEM_INFERENCE` 不得为 `ACTIVE`，只能进 PENDING。有 CI 断言 | `04` §3.5 |
| 「多只猫会串味吗？」 | `pet_id` 是存储层必填参数，不靠调用方自觉；污染率评测要求 0 | `04` §7 |
| 「为什么用 LangGraph？」 | 需要条件路由 + 状态归约 + 可观测 trace。**不是因为流行** | `01` §2 |
| 「为什么不用 ReAct？」 | 任务边界封闭，循环只增加不确定性；概率计算必须可复现 | `08` §3 |
| 「Agent 出错怎么办？」 | 分级降级：**正确性降级可见，体验降级静默** | `01` §6 |
| 「怎么控制成本？」 | 按节点分别统计 token 与延迟；路由是分类不是长推理；TTS 与记忆写入可异步 | `01` §3 |
| 「怎么评测 Agent？」 | 六类评测集 + 不变量断言 | `05` |
| 「你这个跟调 API 有什么区别？」 | 指向 `04` §3（写入决策管线）+ `03` §3（概率推导）+ `07`（安全设计） | — |

## 6. 现场演示脚本

面试现场演示的顺序，**从「能看见的东西」到「看不见的设计」**：

| 步 | 演示动作 | 展示的能力 |
|---|---|---|
| 1 | 上传 5 张猫照片 → 展示抽取的 `must_keep_features` | 多模态 + 结构化输出 |
| 2 | 展示「多图取交集」的 `observed_but_unstable` 区分 | 工程细节（不是简单堆 prompt） |
| 3 | 闲聊一轮 → 展示 `node_trace`（走了哪些节点、耗时、token） | **Agent 可观测性** |
| 4 | 说「以后记住它怕吸尘器」→ 再问「它怕什么」 | **RAG 闭环** |
| 5 | 同一信息说三次 → 展示记忆列表仍为 1 条、`support_count=3` | **强化机制** |
| 6 | 先说「喜欢逗猫棒」再说「最近不喜欢」→ 展示取代链 | **冲突消解** |
| 7 | 上传猫叫 → 展示 `evidence` 里每项的 `log_odds_contribution` | **概率推理（非 LLM 编造）** |
| 8 | 展示 `evidence_mode = text_only` 时禁止输出数值置信度 | **降级分级** |
| 9 | 查库：`system_inference AND ACTIVE` 条数为 0 | **防自我强化（安全）** |
| 10 | 展示红旗规则表的 `enabled: false` 项与 `disabled_reason` | **审慎与合规意识** |

**第 4–6 步是 RAG 的核心演示，第 3、8、9 步是 Agent 与安全的核心演示。**

> 关键：**不要演示「能聊天」，要演示「系统在特定约束下会怎么做」。**
> 演示拒绝、演示降级、演示不变量成立——这些才是工程能力。
