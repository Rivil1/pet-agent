# 00 · 产品定位与边界

## 1. 一句话定位

> **记录并调取「主人对自己猫的经验」的辅助 Agent** —— 以一只真实存在的猫为长期身份锚点，
> 提供拟人化陪伴、多模态行为解释，并把互动沉淀为可检索的长期记忆。

关键在于「**真实**」：用户不是为了跟一个泛泛的猫娘聊天，而是跟**自己那只猫**。

> **知识对象是「主人的经验」，不是「猫的心思」。**
> 系统**不声称**知道猫在想什么，它声称的是「我记得你上次是怎么处理的」——
> 而这个声称可以被逐条核对。Agent 的角色是**辅助**：档案员 + 检索者 + 归纳者。
> 详见 [DESIGN.md §1.1](DESIGN.md)（决策 D29）。

## 2. 三个核心能力

```
真实猫咪  ──►  身份锚定  ──►  陪伴对话
                 │
                 └──►  行为解释（"它想干什么"）
                          │
                          └──►  沉淀为长期记忆 ──┐
                                                  │
                    ◄─────────────────────────────┘
                       （记忆反哺个性化）
```

| 能力 | 用户动作 | 系统产出 |
| --- | --- | --- |
| **身份锚定** | 上传 3–5 张照片 + 补充描述 | 结构化宠物档案（含必须保留特征） |
| **陪伴对话** | 文字 / 语音 / 图片 | 符合该猫角色设定、且引用真实记忆的回复 |
| **行为解释** | 上传叫声 + 补充场景 | 候选意图排序 + 可追溯证据 + 后验置信度 |
| **健康监测** | 记录饮食 / 砂盆 / 体重 | 与个体基线的偏离提示 + 分诊建议（**不是诊断**） |

## 3. 诚实性声明（本项目最重要的设计约束）

这三条边界不是免责声明，而是**产品可信度的来源**，也是面试时的核心加分项。
任何一条被突破，整个项目就从「AI 系统」退化成「LLM 包装」。

### 3.1 外观一致性校验 ≠ 个体身份鉴定

系统内的向量相似度用于回答：

> 「这张新照片和档案里的猫，**外观是否相符**？」

**不是**回答：

> 「这张照片里的猫**是不是团团**。」

原因：CLIP 类通用图像 embedding 捕捉的是**类别语义**（橘猫 / 圆脸 / 短毛），
不是**个体辨识特征**。两只不同的橘猫余弦相似度同样可能很高。
猫咪个体再识别（animal re-ID）需要专门训练的模型与标注数据，市面无可用现成服务。

**因此**：向量分数只作为**冲突告警信号**（明显不符时提醒用户），
真正的身份约束由 `mustKeepFeatures` 文本特征承担。

> 面试话术：我知道这个工具做不到个体鉴定，所以我把它的定位收窄成外观校验，
> 而不是包装成「我实现了猫咪身份识别」。

### 3.2 意图推断 ≠ 翻译

系统**不产出**「猫咪说：我饿了」这种句式。

系统产出的是：**在给定声学特征、场景与个体历史下，若干候选意图的后验概率排序。**

「翻译」暗示存在一种可逆的符号映射（猫语 → 中文），这在科学上不成立。
本系统做的是 **context classification**：判断叫声最可能产生于哪种情境。

### 3.3 四层信息必须分离

**为什么是四层而不是三层**：早期版本把「用户提供的」与「系统测量的」合并为
「观察事实」，但两者的**可信度来源完全不同**：

- 系统测量是**可复现**的 —— 0.82s 就是 0.82s，重算一次还是它
- 主人的记录里**混着观察与判断** ——「我记成撒娇」是判断，**可能与事实不符**

把两者同级，会让主人的一个错误判断获得与物理测量同等的地位。

| 层 | 定义 | 来源 | 允许的措辞 |
| --- | --- | --- | --- |
| **系统测量** | 从音频 / 图像直接计算，**可复现** | 声学计算 / 视觉测量 | 「叫声时长 0.82s」 |
| **主人记录** | 主人当时**观察到**或**做过**的 | 用户记录（情境 / 动作 / 结果） | 「**你记的是**：开门后它出去了」 |
| **AI 推测** | 基于上两层做的关联与归纳，**必须归属回具体条目** | 声学相似度 / 计数统计 | 「这类叫声你记了 5 次，**其中 4 次**的处理是开门」 |
| **拟人化设定** | 用户为该猫设定的说话风格 | 用户设定 | 「团团表示：本喵饿了」 |

**硬性规则**：拟人化措辞**不得**把推测包装成事实；
**AI 推测的每一句都必须能指回「系统测量」或「主人记录」中的具体条目** ——
指不回去的句子不是推测，是编造。

完整规则见 [DESIGN.md 边界 3](DESIGN.md)。

## 4. 非目标（Non-Goals）

明确不做，避免范围蔓延：

- ❌ 猫咪个体身份鉴定 / 找回走失猫
- ❌ 兽医诊断、判定疾病名称、用药建议、出具诊断书
  —— 健康模块只做**监测与分诊**，边界依据《动物诊疗机构管理办法》，详见 [07-health.md](07-health.md)
- ❌ 实时双工语音通话（TTS 为单轮回复式）
- ❌ 猫语词典 / 逐句翻译
- ❌ 通用宠物助手（本期只做猫；犬类等不做）

## 5. 面试可讲的技术点映射

| 能力 | 项目中的落点 |
| --- | --- |
| Agent 编排 | LangGraph 节点图、意图路由、状态流转 |
| 多模态理解 | Qwen-VL 视觉身份抽取、声学特征提取 |
| RAG / Memory | 宠物档案 + 事件记忆 + 三层检索 |
| 结构化输出 | 档案 / 记忆事件 / 解释结果均强类型约束 |
| 工具调用 | 读档案、检索记忆、记录事件、TTS |
| 状态管理 | 会话状态、情绪状态、任务状态 |
| **概率推理** | **分层贝叶斯收缩，解决新宠物冷启动** |
| **评测体系** | **六类评测集 + LLM-as-judge** |
| 工程化 | FastAPI、多租户隔离、异步任务、可观测性 |
| **AI 安全/诚实性** | **四层信息分离、证据可追溯、置信度阈值** |
| **High-stakes 领域设计** | **健康分诊：确定性规则 + 统计检测双轨、非对称代价、显式「无法评估」态** |

## 6. 产品闭环

```
注册宠物 ──► 建立档案 ──► 日常互动 ──► 行为解释 ──► 记忆沉淀
                  ▲                                    │
                  └────────────────────────────────────┘
                        记忆反哺个性化与解释准确度
```

闭环的价值在于：**互动越多，个体化程度越高**。
这是「数据飞轮」在单用户场景下的具体形态——不靠用户量，靠单只猫的历史积累。
