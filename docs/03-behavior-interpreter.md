# 03 · 行为解释器：证据链与概率推导

> 本文档定义 `behavior_interpreter` 节点的推理机制。
> 这是全项目最容易被追问的部分，也是最容易退化成「LLM 讲故事」的部分。

## 1. 先纠正一个命名：这不是「翻译」

「翻译」暗示存在可逆的符号映射（猫语 → 中文）。这在科学上不成立：
猫的叫声不是离散符号系统，同一段叫声在不同情境下含义不同。

系统实际做的是 **context classification（情境分类）**：

> 在给定声学特征、当前场景与这只猫的历史模式下，
> 判断这段叫声最可能产生于哪一种**情境**。

**情境 ≠ 意图**。这个区分很重要：

| 概念 | 例子 | 可验证性 |
|---|---|---|
| **情境 context** | 「发生在等食时」 | 用户可确认（"对，当时我在开罐头"） |
| **意图 intent** | 「它想吃东西」 | **不可验证**（无法证明猫的内心状态） |

**因此系统的预测目标是 `context`，不是 `intent`。**
展示层再把 context 映射成用户能理解的说法与建议动作。

这解决了一个根本问题：**训练标签从哪来**。
用户能可靠地标注「当时在干什么」，但无法标注「猫当时想什么」。
用不可验证的目标做监督学习，评测就无从谈起。

## 2. 证据链的三个来源

`evidence` 数组里每一项必须能回溯到下面三者之一。**LLM 自身不得产生证据项。**

```
┌────────────────────┐
│ A. 声学测量         │  从音频直接计算，可复现
│    measured        │  → duration / F0 / contour / rate ...
└─────────┬──────────┘
          │
┌─────────▼──────────┐
│ B. 个体历史         │  这只猫过去被确认过的同类叫声
│    retrieved       │  → 最近邻检索，得到个体似然
└─────────┬──────────┘
          │
┌─────────▼──────────┐
│ C. 群体先验         │  CatMeows 等公开数据集的上下文分布
│    prior           │  → 冷启动时的兜底
└────────────────────┘
```

## 3. 推理机制：带证据归因的朴素贝叶斯

### 3.1 目标

给定特征向量 `f = (f₁...f_d)`、猫 `c`、场景 `s`，求：

```
P(context = k | f, c, s)
```

### 3.2 分解

```
                    P(f | context=k, c) · P(context=k | s)
P(context=k|f,c,s) = ────────────────────────────────────────
                                 Z
```

- `P(context=k | s)` —— **场景先验**。用户若描述「对着门叫」，则 `door_attention` 拿到强先验；
  若用户没给场景，退回数据集的基础分布。
- `P(f | context=k, c)` —— **个体似然**。由这只猫的历史样本估计。

### 3.3 对数几率形式（这一步是关键）

朴素贝叶斯假设特征条件独立后，取对数几率：

```
logit(k) = log P(context=k | s)                    ← 场景先验
         + Σᵢ LLRᵢ(k)                              ← 各特征的对数似然比
```

其中单特征对数似然比：

```
              p(fᵢ | context=k, c)
LLRᵢ(k) = log ─────────────────────
              p(fᵢ | context=¬k, c)
```

**这个形式的价值**：每个特征对最终判断的贡献是一个**可打印的数字**。
于是 `evidence` 数组里可以写出：

```
叫声时长 0.82s，长于它日常索食叫声均值 0.41s（+1.34 对数几率）
```

而不是：

```
因为它一直叫，所以它饿了   ← 这才是 LLM 讲故事
```

### 3.4 冷启动：分层贝叶斯收缩

新宠物没有任何历史样本，个体似然无法估计。解决方案是把个体与群体似然做**收缩**：

```
P(f | k, c) = λ_c · P_ind(f | k, c) + (1 − λ_c) · P_pop(f | k)

其中 λ_c = n_c / (n_c + κ)       κ = 收缩常数（经验值 5）
      n_c = 该猫已确认的样本数
```

行为：

| `n_c` | `λ_c` | 效果 |
|---|---|---|
| 0 | 0.00 | 完全用群体先验（冷启动） |
| 5 | 0.50 | 个体与群体各半 |
| 20 | 0.80 | 明显个体化 |
| 100 | 0.95 | 基本个体化 |

**这个设计同时给了产品一个可展示的指标**：`个体化程度 = λ_c`。
用户能看到「系统对团团的了解程度：12%」，随着互动提升——这就是数据飞轮的可视化。

> 面试价值：这是把「RAG 检索」升级为「概率推理」的具体落点。
> 它同时解决了一个真实工程问题（冷启动），而不是为了炫技。

### 3.5 似然估计的具体做法

对每个连续特征，假设各情境内服从高斯分布（对角协方差）：

```
p(fᵢ | k) = N(fᵢ ; μᵢₖ, σᵢₖ²)
```

- 群体参数 `μᵢₖ, σᵢₖ` 从 `data/priors/catmeows_stats.json` 读取（离线统计一次）
- 个体参数由该猫的历史样本估计，样本不足时按 3.4 收缩

选择高斯 + 对角协方差的理由：**可解释、参数少、小样本不爆炸**。
换 GMM 或判别式模型在样本量 <100 时只会过拟合，且无法归因。

## 4. 声学特征清单

提取工具：`librosa` + `pyin`（F0 估计）+ `parselmouth`（可选，Praat 算法）。

| 特征 | 符号 | 提取方法 | 文献依据 |
|---|---|---|---|
| 叫声时长 | `duration` | 能量门限端点检测 | 上下文对其有显著影响 |
| 基频均值 | `f0_mean` | pyin，剔除 voiced 置信度 <0.15 的帧 | 上下文 / 性别 / 年龄均有影响 |
| 基频跨度 | `f0_range` | F0 的 P5–P95 分位跨度 | 同上 |
| 基频轮廓斜率 | `f0_slope` | 对 F0 序列线性拟合 | **正向/亲和情境倾向上升轮廓，负向倾向下降** |
| 叫声速率 | `call_rate` | 单位时间叫声次数 | 索求行为强度的经典指标 |
| 叫声间隔 | `ici_mean` | 相邻叫声起点间隔均值 | 同上 |
| 能量包络 | `rms_mean` | RMS 均值 | 强度 |
| 粗糙度 | `roughness` | 幅度调制深度 | Schrader 声学特征集 |

> 注意 `f0_slope` 的**方向性**含义有文献支持（Melody matters 研究：正面情境上升、负面情境下降/多变），
> 这使得它成为归因中最强、最好解释的单项证据。

## 5. 为什么**不**用 ASR 转写猫叫

这是一个必须在设计阶段就排除的错误方案：

| 项 | 说明 |
|---|---|
| Paraformer 是什么 | **人类语音**识别模型，训练目标是语音 → 文字 |
| 猫叫不是语音 | 无音素结构、无词汇、无语法 |
| 强行转写的后果 | 输出为空、或输出莫名其妙的汉字（模型被迫把噪声映射到最近的音素） |
| 面试风险 | 被问「猫叫没有音素，你怎么转写的」即崩塌 |

**正确做法**：猫叫走**声学特征提取**（第 4 节），不需要任何大模型。
ASR 只用于**用户语音输入**（用户说话 → 文字），与猫叫分析是两条独立链路。

## 6. 输出契约

```jsonc
{
  "evidence_mode": "acoustic_plus_history",   // 或 "text_only"（降级）
  "acoustic_features": {
    "duration": 0.82, "f0_mean": 612.4, "f0_range": 180.2,
    "f0_slope": 0.31, "call_rate": 4.5, "ici_mean": 0.63,
    "rms_mean": 0.14, "roughness": 0.22
  },
  "candidates": [
    {
      "context": "food_waiting",
      "posterior": 0.68,
      "display": "很可能是在等吃的",
      "log_odds": 0.75
    },
    {
      "context": "door_attention",
      "posterior": 0.21,
      "display": "也可能是在关注门外动静",
      "log_odds": -0.13
    }
  ],
  "evidence": [
    {
      "kind": "measured",
      "statement": "叫声时长 0.82s，明显长于它日常索食叫声均值 0.41s",
      "source": "acoustic:duration",
      "value": 0.82,
      "reference": 0.41,
      "log_odds_contribution": 1.34
    },
    {
      "kind": "retrieved",
      "statement": "与它 3 天前喂食前录到的那段叫声特征接近（相似度 0.87）",
      "source": "meow_sample:8f2a...",
      "value": 0.87,
      "reference": null,
      "log_odds_contribution": 0.92
    },
    {
      "kind": "prior",
      "statement": "你提到它同时在盯着食盆",
      "source": "scene_prior:food_waiting",
      "value": null, "reference": null,
      "log_odds_contribution": 1.10
    }
  ],
  "individualization": 0.12,          // λ_c，个体化程度
  "sample_count": 3,                  // n_c，已确认样本数
  "suggested_observation": "观察它是否伴随蹭腿、绕食盆走动",
  "limitations": "仅凭叫声无法确定真实需求；若伴随持续焦躁或异常叫声，建议就医观察"
}
```

### 字段约束

| 字段 | 约束 |
|---|---|
| `posterior` | **由评分层计算**。LLM 不得写入或修改 |
| `evidence[].log_odds_contribution` | 必须能由特征值 + 参考值复算得到 |
| `evidence[].kind` | 只能是 `measured` / `retrieved` / `prior` |
| `candidates[].posterior` 之和 | 归一化到 1.0（开放集情境用 `other` 兜底） |
| `evidence_mode = "text_only"` 时 | **禁止**输出 `acoustic_features` 与 `posterior` 数值 |

最后一条是硬约束：**没有声学证据就不许给数值置信度**。
否则系统会退化成「用户描述什么就顺着说什么」的谄媚模型。

## 7. 置信度的诚实使用

后验概率不是装饰。按最大值分档处理：

| `max(posterior)` | 系统行为 |
|---|---|
| ≥ 0.65 | 给出明确候选 + 主证据 + 建议动作 |
| 0.45 – 0.65 | 只给方向性描述，**不给**具体建议动作 |
| < 0.45 | 明说「无法判断」，只输出建议观察项 |
| 样本数 = 0 且无场景描述 | 直接明说「这是它第一次被记录，样本太少」，不给排序 |

**强制要求**：任何情况下都必须输出 `limitations` 与 `suggested_observation`。
这不是免责，而是把「解释动物行为」这件事的真实不确定性交还给用户。

## 8. 与 LLM 的分工边界

这是保证「证据可追溯」的机制设计：

| 环节 | 谁做 | 做什么 |
|---|---|---|
| 特征提取 | **代码**（librosa） | 计算数值 |
| **案例检索 / 计数** | **代码** | k-NN + 计数（**P0 主路径**，`case_based`） |
| 似然 / 先验 / 后验 | **代码** | 计算概率与对数几率（**群体先验就绪后才启用**） |
| 候选排序 / 分档 | **代码** | 排序与阈值 |
| **措辞化** | LLM | 把结构化结果写成自然语言 |
| **建议观察项生成** | LLM | 基于情境给出可操作的观察建议 |
| **拟人化包装** | LLM | 套上该猫的角色语气（外层，不改变事实层） |

**LLM 禁止事项**（由 `response_guard` 强制检查）：

1. 修改任何概率数字或计数
2. **引入 `evidence` / `similar_cases` 之外的任何陈述** —— AI 推测的每一句都必须能指回
   「系统测量」或「主人记录」中的具体条目（见 [DESIGN.md 边界 3](DESIGN.md)）
3. 把 `candidates` 里的推测表述为确定结论
4. 在**任何非 `acoustic_plus_history` 模式**下给出数值置信度
   （`case_based` / `measured_only` / `text_only` 均禁止）
5. 输出超出 `limitations` 范围的诊断性结论
6. **用「你记的」冒充系统判断，或用系统判断冒充「你记的」** —— 归属必须准确，
   因为归属本身就是安全机制（见 DESIGN.md 边界 3 规则 3）

## 9. 已知局限（面试时主动交代）

主动说出局限比被问出来强得多。

| # | 局限 | 影响 | 缓解 |
|---|---|---|---|
| L1 | CatMeows 仅 21 只猫 / 2 个品种（缅因 + 欧短） | 群体先验对家养田园猫可能不具代表性 | **P0 不用群体先验**（改走 `case_based`）；该局限仅影响休眠的 `acoustic_plus_history` 路径 |
| L1b | **主人标注负担**：新用户需记 5–10 次才能显出价值 | **产品成败关键** —— 用户会不会记？未知 | 记录做到 10 秒内完成；nudge 式邀请而非催促；冷启动也提供测量值 |
| L2 | 数据集只有 3 类情境（梳毛 / 隔离 / 等食），无 `door_attention` | 真实家庭情境覆盖不全 | 用文献中的 7 情境分布补充，并保留 `other` |
| L3 | 环境噪声与麦克风质量影响 F0 估计 | 特征噪声大 | 记录录音质量指标，低质量时降低置信度 |
| L4 | **个体样本标签本身不可验证** | 用户标注的「情境」可能与猫的真实状态不符 | 明确标注目标是 context 而非 intent（见 §1） |
| L5 | 朴素贝叶斯假设特征条件独立 | F0 与 duration 实际相关，似然被高估 | 置信度做温度校准；不对外暴露绝对值语义 |
| L6 | 单次叫声信息量有限 | 同一声叫可能对应多个情境 | 强制输出多个候选 + alternative |

> L4 与 L5 是最容易被追问的两点。L4 的回答是「所以我把预测目标从 intent 降级为 context」，
> L5 的回答是「所以我用温度校准而不断言绝对概率」——两个回答都指向同一个设计原则：
> **不声称超出数据能支撑的东西。**

## 10. 降级路径

```
音频可读？
  ├─ 否 → evidence_mode = "text_only"，只用场景描述 + 历史记忆做文本推断
  │        （禁止输出 posterior 数值）
  └─ 是 → 特征提取
           ├─ 失败 → 同上降级，并在 errors 中记录原因
           └─ 成功 → 似然计算
                     ├─ 无个体样本 (n_c = 0) → λ_c = 0，纯群体先验，标注「冷启动」
                     └─ 有个体样本 → 收缩估计
                              ↓
                         归一化 → 分档 → 措辞化 → guard
```

## 11. 可复现性要求

为了让「证据」这个词站得住，以下必须成立：

1. **同一段音频 → 同一组特征**：特征提取需固定随机种子、固定重采样率
2. **同一组特征 → 同一组后验**：先验文件版本化（`priors/catmeows_stats.json` 带 `version` 与 `sha256`）
3. **每次解释结果落库**：记录 `features`、`prior_version`、`posterior`，
   以便事后审计「当时为什么给出这个判断」
4. **用户反馈可回写**：用户点「不对，它其实是 XX」→ 作为新样本写入，参与下一轮似然估计

第 4 条就是数据飞轮在解释链路上的具体接口，详见 [04-memory.md](04-memory.md)。
