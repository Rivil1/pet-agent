## 1. P0 · 内容矛盾

### D1 · `docs/00` 把**被禁止**的拟人化示例当作示范

| 位置 | 内容 |
| --- | --- |
| `00-product.md:70` | 拟人化设定的**允许**示例：「团团表示：**本喵饿了**」 |
| `12-anthropomorphism.md:166` | 「本喵饿了」→ **禁止**（影响照料决策，可能导致过量喂食） |

**两份文档对同一个例子给出相反判定，而 `00` 是产品文档、优先级更高。**
更糟的是 `00` 的示例恰好是 `12` 花整节论证要禁止的模式。

**根因**：`00` §3.3 写于 `12` 之前，`12` 新增了「按照料决策划分适用范围」这条规则，
但 `00` 没有回改。

### D2 · 行为解释的输出：`docs/00` 用了被 `docs/03` 否定的术语

| 位置 | 内容 |
| --- | --- |
| `00-product.md:27` | 产出「候选**意图**排序」 |
| `00-product.md:59` | 「若干候选**意图**的后验概率排序」 |
| `03-behavior-interpreter.md:23` | 「系统的预测目标是 `context`，**不是 `intent`**」 |

`03` §1 用整节论证「情境 ≠ 意图」是核心区分（因为用户能标注情境、不能标注意图，
用不可验证的目标做监督学习则评测无从谈起）。而 `00` 两处都用了被否定的词。

### D3 · `docs/08` 的意图数量过期，且它是核心论证的基础

| 位置 | 内容 |

## 6. 根因分析

### 根因一：**声明 ≠ 登记**

> 每篇文档都在**声明**同步需求，但没有任何地方**登记**它们。

`docs/11`–`14` 都写了「对既有设计的影响」章节，写得很认真。
但它们散落在 4 篇文档的末尾，且是**自然语言段落**而非**可勾选清单**。
没有任何机制检查执行情况。

### 根因二：同一事实在多处重复表述，没有单一事实来源

| 事实 | 出现在 | 是否一致 |
| --- | --- | --- |
| 六类评测集 | `00` / `06` / `08` | 一致但**无定义** |
| 拟人化示例 | `00` / `12` | **不一致** |
| 行为解释的输出 | `00` / `03` | **不一致** |
| 意图数量 | `08` / `09` / 契约 | **不一致** |

同一事实写 3 遍，改的时候只改 1 遍 → 必然漂移。

### 根因三：审查靠人眼

在 `scripts/doc_check.sh` 之前，文档一致性只能靠人工翻阅 4,550 行。
`10-self-review.md` 之所以能发现问题，是因为当时**逐条 grep 核实**；
但那次审查只覆盖了设计，没覆盖文档体系本身。

         架构与产品对齐

## 9. 防复发机制

### 9.1 自动检查（已建）

```bash
bash scripts/doc_check.sh
```

覆盖 7 类检查：索引与实际文件、内部链接、术语冲突、数字一致性、
同步债、已修问题的表述、被引用的数据产物。

**建议**：每次改完文档跑一次；后续可接入 CI。

### 9.2 单一事实来源原则

> **一个事实只在一处定义，其他地方引用。**

| 事实 | 唯一定义处 | 其他地方 |
| --- | --- | --- |
| 意图清单与数量 | `app/schemas/input.py` 的 `InputIntent` | 只说「见契约」，不重复数字 |
| 评测项 | `docs/05-eval.md` | 引用章节号 |
| 拟人化边界规则 | `docs/12` §3 | 引用，不重复表格 |
| 术语定义 | `docs/GLOSSARY.md` | 用规范名，不再解释 |
| 同步债 | `docs/15` §7（本表） | 不再各自维护清单 |

### 9.3 改动文档时的固定动作

1. 改了某个决定 → 在 §7 表中登记需要同步的文档
2. 同步完 → 勾选
3. 跑 `scripts/doc_check.sh`
4. 若新增术语 → 进 `GLOSSARY.md`

### 9.4 一个反直觉的观察

本项目的文档问题**不是写得不够，而是写得太多**：

```
4,550 行 / 15 篇
同一事实平均被表述 2–3 次
```

**冗余是漂移的温床。** 后续应倾向于：

- 宁可一篇文档写长，不要同一内容拆到三处
- 引用优于复述
